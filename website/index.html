go-boilerplate

一套开箱即用的 Go 后端脚手架：把后端常见基础设施一次性集成好，让你专注业务。

Go 1.26 Gin GORM ×3 数据库 JWT + Casbin RBAC OTel / Prometheus WebSocket + SSE gRPC（build tag）

go-boilerplate 集成了现代 Go 后端所需的 HTTP 框架、ORM、缓存、消息队列、认证授权、 结构化日志、链路追踪、监控、实时通信、gRPC、配置中心与定时任务。所有第三方组件均通过 统一开关矩阵控制，可按需裁剪，缺省全部开启。

设计目标：零改造即可启动一个具备生产可观测性（日志 / 追踪 / 指标）、 多数据库兼容、可热更新配置的微服务骨架；业务代码只写 internal/ 下的 handler / service / repository。

快速开始

前置要求

  • Go 1.26.0（本项目锁定；用 gvm 管理多版本时先切到 1.26.0）。
  • 目标数据库（MySQL 8 / PostgreSQL 16 / SQLite 任一）；默认 SQLite 可零依赖启动。
  • 可选：启用 gRPC 需 brew install protobuf + go install protoc-gen-go / protoc-gen-go-grpc。

运行（默认 SQLite，零外部依赖）

# 切到锁定版本
gvm use 1.26.0          # 或 export PATH="$HOME/.gvm/gos/go1.26.0/bin:$PATH"

# 拉取依赖
go mod download

# 启动服务（自动建表 + seed 管理员）
go run ./cmd/server

# 执行数据库迁移（如需单独跑）
go run ./cmd/migrate up

启用 gRPC

所有 gRPC 代码以 //go:build grpc 隔离，默认构建跳过。启用流程：

# 1. 安装 protobuf 工具链（仅一次）
brew install protobuf
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest

# 2. 由 .proto 生成代码
make proto

# 3. 带 build tag 编译
go build -tags grpc ./cmd/server
数据库切换：database.type 设为 mysql / postgres / sqlite， 统一走 pkg/database.New 初始化。SQLite 建议 max_open_conns: 1。

配置参考

配置文件位于 configs/config.yaml，由 viper 加载。配置中心（Nacos / Apollo）可在运行时热更新， 产出完整 YAML 经 atomic.Pointer 替换，业务通过 config.Get() 读取最新值。连接类组件启动时初始化一次，不随配置热重建。

# configs/config.yaml 关键节点
database:
  type: sqlite                 # mysql / postgres / sqlite
  dsn: "./boilerplate.db"      # 或 RawDSN
  max_open_conns: 1            # sqlite 建议 1

config_center:
  enable: false
  type: local                 # local / nacos / apollo

cron:
  enable: true
  location: "Asia/Shanghai"
  jobs:
    - name: heartbeat_tick
      spec: "@every 30s"
      description: 心跳

# 组件开关（见下节「组件开关矩阵」）
redis:    { enable: true }
auth:     { enable: true }
realtime: { enable: true }
docs:     { enable: true }
metrics:  { enable: true }
grpc:     { enable: false }
otel:     { enable: true }
registry: { enable: false }
rocketmq:
  producer: { enable: false }
  consumer: { enable: false }
字段命名：数据库 DSN 字段用 RawDSN（mapstructure: dsn），因其不能与 DSN() 方法同名。配置中心热更新时会保留 ConfigCenter 段。

组件开关矩阵

所有 enable 字段缺省为 true。关闭某项即移除其依赖与路由，降低资源占用或简化部署。

开关默认关闭时的行为
redis.enabletruerdb=nil；/readyz 跳过 redis 检查（输出 redis: disabled）
auth.enabletrue不挂 JWT / Casbin 中间件；users 路由放行
realtime.enabletrue不挂 /ws、/sse
docs.enabletrue不挂 /swagger/*any
metrics.enabletrue不挂 Prometheus 中间件、不暴露 /metrics、不注册 GORM / Redis hook
cron.enabletruepkg/cron.New/Start/Stop 变为 no-op，零开销
rocketmq.producer.enablefalse不初始化生产者
rocketmq.consumer.enablefalse不启动消费组
grpc.enablefalse不注册 gRPC server（需 build tag grpc）
registry.enablefalse不向注册中心注册
otel.enabletrue不初始化 OTLP 导出
config_center.enablefalse仅用本地 YAML

HTTP 路由与探针由 router.Toggles{...} 收敛前五个开关；/readyz 允许 rdb=nil， 仅当依赖真正 down 才返回 503（disabled 不触发）。

部署

容器化（推荐）

仓库根目录提供 docker-compose.yml，含应用、Prometheus 与 Grafana，一键拉起可观测栈：

docker compose up -d

二进制

go build -o bin/server ./cmd/server
./bin/server

启用 gRPC 时加 -tags grpc。生产建议配合反向代理（Nginx / Caddy）暴露 /api/v1 与 /metrics。

文档站点（GitHub Pages）

本站由 website/ 目录托管，经 GitHub Actions（.github/workflows/pages.yml）在每次 push 到 main 时自动构建并部署到 GitHub Pages（仓库 Pages 源设为 GitHub Actions，不污染任何分支）。

本站点为纯静态 HTML，零构建依赖：CI 仅把 website/ 作为 Pages artifact 上传并部署，无需 Node / Python 工具链。

开发指南

gRPC 隔离

所有 gRPC 代码以 //go:build grpc 隔离。默认 go build 跳过；启用需先 make proto 再 go build -tags grpc。

测试

项目采用白盒单元测试，关键路径覆盖率目标 >80%。基础设施包（redis / otel / mq / registry）依赖外部服务，留待 CI service 容器覆盖。

# 全量测试
go test ./...

# 单包（如配置）
go test ./internal/config/...

# 覆盖率
go test -cover ./...
测试约定：数据库相关测试用 SQLite :memory: 单连接（MaxOpenConns:1）； HTTP 层用 httptest + gin 真栈端到端验证；JWT 有效期是 time.Duration，测试里必须写 900 * time.Second（裸 900 会被当 900ns 导致 token 瞬时过期）。

初始化与种子

首次启动（auto_migrate: true 默认开启）会自动建表，并 seed 一个管理员账号与 Casbin 初始策略：

  • 管理员：admin / admin123
  • Casbin 策略：admin 全权限；user 只读用户详情
安全提示：种子账号仅用于本地 / 演示。生产部署请务必修改默认密码，或通过环境变量 / 配置中心注入凭据。
